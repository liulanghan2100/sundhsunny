# 对抗式辩论协议（debate-protocol）

把任何一个「需要拍板」的议题，拆成强制对立的支持/反对两方来对抗论证，最后由主持人综合成结构化决策。蒸馏自 TradingAgents 的多空研究员辩论机制——它解决单模型决策的「过度乐观」「墙头草」问题。

## 触发词

「辩论」「多空」「对抗评审」「方案PK」「两方观点」「正反论证」「支持还是反对」「利弊权衡」「红队」「魔鬼代言人」

## 何时用 / 何时不用

**用**：需要决策质量的关键判断（是否投资、方案选型、评审他人提案、风险权衡）；结论会被采信且代价高时。
**不用**：纯信息检索（直接查答案）；单方事实核查（用 research）；无实质分歧空间的议题（辩论是浪费）。

## 核心流程（5 步，每步可执行）

### 第 1 步：准备事实包（必须先做，无事实包不辩论）
- 收集议题相关数据/证据/历史案例，写入事实包（列表形式，每条标注来源）
- 事实包不足时先调用 research 补全，禁止空手开辩

### 第 2 步：立场隔离生成（关键机制）
- 生成两个隔离的立场角色：**支持方**（必须找出支持证据）与**反对方**（必须找出反对/风险证据）
- **禁止**同一推理链先后扮演两方（容易墙头草）；两个立场独立产出
- **单模型退化方案**（本地执行必看）：当两方只能由同一 LLM 产出时，必须分两次独立生成——先产出支持方并落盘，再在不引用支持方内容的前提下产出反对方；主持人综合时须显式标注「本次辩论为单模型隔离模拟，对抗强度弱于多模型混配」
- 每方产出 ≥3 条带来源的证据，证据格式：`{主张, 事实依据, 来源可信度(高/中/低)}`

### 第 3 步：交叉质询（至少 1 轮）
- 双方轮流向对方证据发起质询：要求补充依据、指出逻辑断裂、攻击前提假设
- 质询规则：只攻击证据与论证，禁止攻击立场本身（「你就是不看空」这类话无效）
- 对无法回答的质询，必须诚实标注「未回答」

### 第 4 步：回应修订
- 双方根据质询结果修订或强化证据清单，标注哪些论点被削弱

### 第 5 步：主持人综合（结构化输出）
- 主持人提取：共识点 / 分歧点（逐条列出）/ 未解决风险
- 输出决策结论 + 置信度（高/中/低），置信度低时必须说明主要不确定性来源

**输出格式**：

```text
议题：
支持方证据：...
反对方证据：...
共识：...
分歧：...
关键风险：...
综合结论：{建议|保持|反对}
置信度：{高|中|低}（低时说明原因）
```

## 检查清单

- [ ] 事实包已落盘（含来源），无事实包已中止
- [ ] 两个立场独立产出（无串通）
- [ ] 每方 ≥3 条带来源可信度的证据
- [ ] 交叉质询 ≥1 轮
- [ ] 未回答的质询被显式标注
- [ ] 主持人输出结构化结论（共识/分歧/风险/置信度）

## 反模式黑名单

- ❌ 无事实包直接辩论（空谈）
- ❌ 同一模型写「支持理由」再写「反对理由」就当辩论（那是列举，不是对抗）
- ❌ 主持人当裁判直接下结论，不让双方交锋
- ❌ 只输出观点不给证据
- ❌ 把辩论结论当「真理」而非「经对抗检验的估计」

## 诚实边界（≥3 条）

1. **辩论不消除认知盲区**：双方都漏掉的关键事实不会因辩论出现——事实包质量决定辩论上限。
2. **提升的是稳健性，不保证正确性**：辩论暴露风险与分歧、防止过度乐观，但结论仍可能错。实证（TradingAgents 论文 arXiv:2412.20138）多智能体辩论在回测中优于单模型；但 STOCKBENCH（arXiv:2510.02209）显示 LLM 交易整体不跑赢 buy-and-hold。
3. **决策辅助协议，不构成投资/法律/医疗建议**：涉交易议题不得用于实盘自动下单（对齐 math-model-selector 红线）。
4. **效果依赖底层 LLM 的论证能力与诚实度**：模型若系统性乐观或悲观，辩论只会放大该偏差。
