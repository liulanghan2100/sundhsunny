# 决策复盘闭环（decision-review-loop）

让每个重要决策都留下可对照的记录，到期强制回头看，把"对/错"归因成教训喂回下一次决策。解决的是**决策没有反馈回路、同一坑踩两次**的问题。蒸馏自 TradingAgents v0.2.4+ 的持久化交易记忆 + 自动复盘（对照基准）与 FinMem 分层记忆。

## 触发词

「复盘」「登记这个决策」「上次那个判断怎么样了」「回顾一下」「教训」「记下来以后看」

## 何时用 / 何时不用

**用**：任何会被未来结果检验的决策（投资判断、方案选型、技术押注、项目立项）落定之后；到达复盘日期时；做同类新决策之前（检索教训）。
**不用**：无结果可对照的偏好型选择（午饭吃什么）；一次性执行类任务（没有"决策"只有"动作"）；纯记录流水账（那不叫复盘）。

## 存储底座

嫁接在 `experience-memory-mcp`（`03_分工MCP/experience_memory_mcp`，11 个工具已静态核验齐全，JSONL 落盘）上，**不另造存储**：

**首选写路径 = `memory_bridge.py`**（`09_投研/agent_fund_studio/memory_bridge.py`）：直接写
experience-memory 的 JSONL 事实源（`09_投研/experience_memory/memory.jsonl`，与 MCP 工具同一
schema），MCP 运行时不可用也照常落记忆（纯标准库回退），**不再出现「待补录」**。
`record-decision` 自动带 `review_date`/`invalidate_when` 字段，供复盘到期触发器扫描。

| 闭环环节 | 使用的工具 |
|---|---|
| 决策登记 | `memory_bridge.py record-decision`（= MCP `record_decision` + 失效条件/复盘日期） |
| 到期对照 | `memory_bridge.py` 检索 + MCP `record_outcome` |
| 教训写回 | `memory_bridge.py record-lesson`（高价值标 `--rule-candidate`） |
| 决策前检索 | `memory_bridge.py search` / MCP `search_memory` |
| 阶段汇总 | MCP `summarize_project` / `memory_brief` |

## 核心流程（4 步闭环）

### 第 1 步：决策登记（决策落定后立即做）
登记以下字段，缺一不可：
- **标的/议题**：决策对象
- **结论**：具体判断（含方向与档位）
- **理由链**：当时依据的 3 条核心论据（带来源）
- **置信度**：高/中/低
- **失效条件**：什么发生时此决策被证伪（预先写下，事后不许改）
- **复盘日期**：明确到期日（投资决策建议 1-3 个月，技术选型 1 个里程碑）

### 第 2 步：到期对照（到复盘日期强制做）
- 取真实结果与登记结论对照，**引用失效条件原文**，禁止事后重述当时的理由
- 结果尚未明朗 → 顺延一次并记录，不得假装已复盘

### 第 3 步：归因（四象限，拒绝结果论）
| | 结果好 | 结果差 |
|---|---|---|
| **理由链成立** | 判断对 ✅（可提炼为经验） | 判断错 ❌（重点解剖：哪条论据错了） |
| **理由链不成立** | 运气对 ⚠️（**不得记为经验**，标注"运气"） | 运气错（检查失效条件为何没拦住） |

- 归因必须有证据，"感觉当时判断没错"不算
- 运气对是本病最常见反模式——赚钱/成功的决策不一定是好决策

### 第 4 步：教训写回 + 下次检索
- 教训写成可执行句式（"下次遇到 X 先查 Y"），`record_lesson` 写回
- 同类新决策开始前，`search_memory` 检索相关教训并显式引用——**检索不到也要记录"无历史教训"，防止假装有积累**

## 检查清单

- [ ] 决策登记含失效条件（预先写下）与复盘日期
- [ ] 复盘时引用了登记的原文，未事后修饰
- [ ] 归因落在四象限之一且有证据
- [ ] 运气对的结果未被记为经验
- [ ] 教训是可执行句式并已写回记忆
- [ ] 下次同类决策前执行了检索并记录检索结果

## 反模式黑名单

- ❌ 结果论：用结果好坏直接判定决策质量（运气对最害人）
- ❌ 事后改理由：复盘时重述"当时其实想到了"
- ❌ 只登记不复盘（闭环断在第 1 步，等于日记）
- ❌ 只复盘成功/盈利决策，回避失败样本（幸存者偏差）
- ❌ 教训写成口号（"要谨慎"），不可执行
- ❌ 新决策前不检索，闭环断在第 4 步

## 诚实边界（≥3 条）

1. **复盘提升的是学习速度，不是命中率**：单次归因样本量太小，需多次闭环后教训才有统计意义；前几次归因结论应标低置信。
2. **结果滞后与混杂因素**：很多决策的结果受市场 beta、环境变化主导（KTD-FIN 归因结论），四象限归因无法完全剥离运气成分。
3. **依赖登记纪律**：本闭环的全部价值建立在"决策落定即登记、失效条件预先写"上；补登记的决策卡（事后回忆）必须标注，其归因权重降级。
4. **不自动改规则**：教训标 `rule_candidate` 后仍需走 feedback_loop 与门禁才能写回手册，本技能不自动修改任何规则。
5. **到期提醒依赖定时任务注册**：`09_投研/agent_fund_studio/review_due.py` 扫描
   `decision_record.review_date` 输出到期清单，过期 → 退出码 1；需把它注册为定时任务
   （`09_投研/agent_fund_studio/blueprint_review_due.yaml` 含 Windows/Daimon 注册说明）才算
   自动触发。✅ 已注册（2026-08-10，任务名 `jiran-review-due`，周频周一 09:00）。
