# 麦肯锡结构化思维

> 给结构，不给答案。框架让你把问题拆对、把结论说清——答案仍然要靠事实。

## 何时使用 / 何时不使用

| 使用 | 不使用（红灯区） |
|---|---|
| 模糊需求拆解（立项、方案设计） | 头脑风暴/探索期（结论先行会扼杀发散） |
| 方案评审（检查不重不漏） | 应急抢修（七步流程来不及走全程） |
| 汇报写作（结论先行） | 情感沟通场景（结构性表达显冷漠） |
| 假设验证类工作规划 | 无事实基础的全新领域（IH 形同猜测） |

**触发红灯后的拒用动作**（三步，不可省略）：① 声明「本框架不适用」→ ② 说明命中的红灯条目与原因 → ③ 指出替代路径（如：发散讨论 / 应急三步压缩版 / 先补事实基础再来）。禁止识别红灯后沉默硬套。

## 主工作流（拿到问题后的标准动作）

1. **界定问题**：区分业务问题与技术问题；写下北极星指标（可量化、有基线）。🔴 问题界定不清 → 停下来重述，禁止带着模糊问题进入拆解
2. **MECE 拆解**：画议题树/因素地图，横向有逻辑、纵向 MECE；自检两句：分点之间有没有交叉？合起来有没有漏掉一大块？
3. **假设排序**：对每个关键因素写下假设，按 影响力×验证难度 打分；先攻高影响+低难度（Quick-Win）
4. **验证迭代**：以假设和最终产品为导向收集证据；假设被事实推翻 → 改假设，不护短
5. **金字塔表达**：SCQA 序言开场 → 塔尖结论 → 3±2 个分论点 → 逐层论据

## 核心框架（4 个）

### F1 MECE 分类
- **定义**：相互独立、完全穷尽（Mutually Exclusive, Collectively Exhaustive）
- **应用步骤**：列问题清单 → 逐条检查是否独立、是否穷尽 → 不确定条目放「其他问题」（但不放清单头条）→ 确认分类维度服务于意图
- **维度选择启发式**（选维度比不重不漏更优先）：按价值链/流程阶段拆（售前→售中→售后）/ 按用户生命周期拆（获客→激活→留存→召回）/ 按公式因子拆（利润=收入−成本，再逐层展开）/ 按对立面拆（内部↔外部、主观↔客观）。四种都不合身 → 说明理由后自定义维度
- **失效条件**：分类维度本身选错时，MECE 只是整齐的错误；过度追求穷尽拖慢节奏（用 80/20 制衡）
- **警惕虚假 MECE**：看似独立实则重叠的分类（如同时按「年龄」和「生命周期」划分人群）

### F2 假设驱动与议题树
- **定义**：工作启动前形成初始假设（IH），将为证实/证伪它必须回答的问题分解为议题树
- **应用步骤**：研究事实概观 → 拆关键驱动因素 → 每个因素提可行性假设 → 分解为议题树 → 逐层回答（任一层为否则假设受威胁）→ 事实推翻则调整假设
- **失效条件**：全新未知领域无事实基础时 IH 是猜测；护假设不认错则全盘皆输——必须配批判机制（3-4 人互检或对抗评审）

### F3 金字塔原理
- **定义**：结论先行、以上统下、归类分组、逻辑递进
- **应用步骤**：SCQA 写序言（情境→冲突→疑问→回答；对高阶层用 A-S-C 开门见山式）→ 塔尖一句话结论 → 第二层 2-4 个分论点（不超 5 个）→ 归纳/演绎填论据 → 全文检查每段首句为中心句
- **逻辑递进三选一**：时间顺序 / 结构顺序 / 程度顺序，同层只能用一种
- **失效条件**：探索性讨论阶段不宜结论先行；读者需要共同推导过程的教学场景，可改为 Q-S-C-A

### F4 七步成诗（问题解决主流程）
- **定义**：界定问题 → 分解问题 → 淘汰非关键议题 → 制定工作计划 → 关键分析 → 综合分析建论证 → 阐明观点
- **应用步骤**：见主工作流（本 skill 主工作流即七步的实战浓缩）
- **关键心法**：淘汰步骤不仅问「那又会怎样」，还要问「你忘了什么」；「提前开始工作，不等数据搜集完毕」；七步是串行理想型，实战允许来回穿梭
- **失效条件**：应急场景来不及走全程（压缩为 界定→拆解→行动 三步）；问题本身界定错误时，七步会高效地解决错误的问题——回到第 1 步重述问题

## 流派与分歧

| 流派 | 侧重 | 使用注意 |
|---|---|---|
| 原典派（Minto/Rasiel） | 表达逻辑 + 假设驱动原汁原味 | 案例偏欧美语境 |
| 日系培训派（大岛祥誉系） | 工具化混搭（空雨伞、零基准、5W2H） | 掺入非麦肯锡工具，勿当原典引用 |
| 实战应用派（七步培训材料/7+2 变体） | 步骤扩容（SMART 界定、who/when/how 行动方案） | 步骤粒度不统一，以多源一致主干为准 |

## 反模式黑名单（绝不做的事）

| # | 反模式 | 替代做法 |
|---|---|---|
| 1 | 把「要做一个模型/功能」当目标 | 永远先写北极星业务指标 |
| 2 | 未拆解就直接给方案 | 先画因素地图再谈方案 |
| 3 | 同层分点交叉重叠（虚假 MECE） | 换分类维度重拆 |
| 4 | 细节铺垫半天，结论压底 | 结论先行，理由随后 |
| 5 | 分论点超过 5 个 | 砍到 2-4 个，其余归并或降级 |
| 6 | 数据没齐就不开工 | 按 IH 提前开工，验证中补数据 |
| 7 | 假设被推翻后护短 | 改假设；记录推翻证据 |
| 8 | 自己评审自己的拆解 | 找第三方批判或走对抗评审 |
| 9 | 语言层 AI 腔：空泛动词与黑话（赋能/抓手/闭环/链路/沉淀）、连接词堆砌（首先/其次/综上/总而言之）、无信息量的正确废话 | 每句话必须含一个事实、数字或动作；拿不准就删掉该句 |

## 诚实边界

1. 核心框架基于二手转述多源交叉验证，原典覆盖率有限（一手来源占比约 27%）
2. 框架给结构，不给答案——不替代行业 know-how 与真实数据
3. 「麦肯锡方法」流传版本众多（七步 / 7+2 / 五步法），本 skill 取多源一致主干，分歧已标注
4. 调研截止：2026-07-31
