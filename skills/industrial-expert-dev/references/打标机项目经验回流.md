# 打标机项目经验回流

## 项目暴露的问题

Zebra/打标签软件项目证明：先做打印引擎是对的，但 UI 如果只做外壳，会导致用户认为软件不可用。

曾暴露的问题包括：

- 菜单页面没有真实路由。
- 对象不能拖拽/缩放。
- 二维码/一维码属性不足。
- 文本、码类内容没有 PLC 变量绑定。
- 打印预览、ZPL 预览、标签预览不足。
- 打印机状态、PLC 交互信号需要直接显示。

## 固化规则

以后做打标/打印/标签设计软件时，验收矩阵必须包含：

- 打印机 IP/端口配置。
- PLC 触发、停止、复位、完成、Ready、Error 信号。
- 模板管理：新建、保存、打开、程序号绑定。
- 对象设计：文本、条码、二维码、DataMatrix、图片、线条、矩形。
- 对象交互：拖动、缩放、属性弹窗。
- 数据绑定：固定值、PLC 变量、序列号、日期时间。
- 预览：标签预览、打印预览、ZPL 预览。
- 追溯：打印结果、序列号、模板号、PLC 数据、错误。

## 设计红线

- 菜单不能只是改标题。
- 工具栏按钮必须创建真实对象。
- 预览不能是假图。
- 配置必须能保存。
- 未接真实打印机时必须标明 dry-run 或模拟模式。
