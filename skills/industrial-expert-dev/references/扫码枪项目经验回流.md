# 扫码枪项目经验回流

## 项目暴露的问题

扫码枪 PLC 采集软件第一次 MVP 跑通了扫码、SQLite、PLC 校验和 EXE 发布，但用户测试后指出三个基础缺口：

- 没有 IP 地址设置。
- 没有数据库查询。
- 没有交互状态。

第二轮补齐后，又明确了不做真实硬件测试时的软件闭环要求：

- 配置必须持久化。
- 查询必须可筛选。
- 导出必须真实生成文件。
- 操作日志必须可查。

## 固化规则

以后做扫码、追溯、PLC 校验软件时，开工前必须在验收矩阵中列入：

- 扫码枪协议：RS232、TCP Server、TCP Client。
- 扫码枪 IP/端口/串口配置。
- PLC IP/端口/地址映射。
- 交互状态：收到扫码、写库、发送 PLC、PLC 返回、ACK。
- 数据库查询：时间、条码、结果。
- CSV 导出。
- 操作日志查询。
- 配置持久化。
